# Dev tools and the sandbox workflow (devtools agent, 2026-10-10)

Branch `devtools/sandbox` (from `integration/round3-2026-10-10`). Every feature is now built, tuned, tested and
reviewed against named, reproducible **scenarios** and a compact developer map (the **lab**), instead of each
script hand-building state on the real maps. The rules are in `AGENTS.md` (Definition of done), `PLAYBOOK.md`,
`docs/EXTENDING.md` section 0 and both briefs.

## Quick start

```sh
npm run dev                                   # then open http://localhost:5195/?scenario=coop-hens
npm run build && npx vite preview             # a build needs ?debug&scenario=coop-hens
npm run verify:fast                           # inner-loop gate (lint, types, unit, build, bundle, smoke e2e)
npm run verify                                # the full gate, suites in parallel
SCENARIO=lab PROFILE=se HAND=left node agents/probes/scenario-template.mjs   # a probe, screenshots in agents/out/shots
```

- **Scenarios**: `src/dev/scenarios/<name>.json`, 18 seeded: `day1-fresh`, `ripe-plot`, `mailbox-mail`,
  `bin-produce`, `coop-hens`, `machines-ready`, `fishing-spot`, `mine-nodes`, `town-clay-race`, `festival-day`,
  `winter-night`, `late-game-farm`, `guided-day2`, `left-handed`, `reduced-motion`, `lab`, plus `farm-mechanics` and
  `spring-meadow` (e2e benches). Format: `ScenarioDef` in `src/dev/scenarios.ts` (semantic keys `at`, `time`,
  `weather`, `money`, `energy`, `items`, `select`, `crops`, `soil`, `placed` with `ready`, `forage`, `nodes`,
  `friends`, `goal`, `stats`, `letters`, `mail`, `shipping`, `tutorial`, `hints`, `settings`, `plots`, `upgrades`,
  `preset: "lab"`, `dev: { seed, clock, clockScale }`, and a raw `state` patch written at `version`). The state is
  today's new game with seed 12345, the raw patch migrated from the fixture's version, then the semantic keys through
  today's rules, then `migrate` again. A scenario page is a sandbox: saves go to memory, your real save is never
  touched.
- **The lab** (`?scenario=lab`): a 26x34 debug-only map. West and east beds hold every crop at every stage (one crop
  per row) and the soil states (tilled, watered, fertilized, weeds, bare dirt to paint rows on); every placeable and
  machine (animals home, machines finished, fruit trees bearing) lines the road; the four ore nodes sit in a quarry;
  forage on the meadow; water along the shore; the shop front, the board and the bin on the north road; a house door
  that teleports to the shore; villagers stand on their spots all day. Generated by `npm run gen:lab`
  (`scripts/generate-lab-map.mjs`, separate from `generate-maps.mjs`; it only reads `map-art.mjs` to dress the
  lab like the real maps). Art tiles are stored by name and resolved against the live `tiles.json`, so a tileset
  rebuild never leaves the lab on the wrong tiles. Registered at runtime only: no door leads there.
- **`window.__farm.dev`** (typed: `src/dev/api.ts`): `load(name)`, `build(name)`, `scenarios()`, `clock.pause/
resume/scale`, `loop.pause/resume/step(n, dt)`, `seed(n)`, `time.set({ clock, day, season, year })`,
  `time.skipDays(n)`, `goto(map, tx, ty)`, `tileToScreen`, `screenToTile`, `frameStats()`, `menu`, `overlay`, and
  the awaits `wait.until / frames / event / sceneReady / transitionDone / panelOpen / panelClosed / actionDone / idle`.
- **Dev menu**: the DEV tab (top-left, over the read-only HUD) with `?scenario=`, `?devmenu` or in `npm run dev`;
  backquote toggles it. Scenarios, maps, clock on/off and speed, +1 hour, freeze, step 1 / 10 frames, the frame graph
  (fps, ms, JS ms, draw calls), the tile grid with coordinates of the player and the last touch, next day (a full
  rollover without the sleep screens). It is HTML: no Phaser scene, no draw call, no game touch target.
- **`scripts/lib/farm.mjs`**: `serve(port)` (or `URL=` a running server), `launch()`, `openScenario(browser, url,
name, { profile, hand, query })`, then `farm.act()`, `interact()`, `select(slot)`, `press(key)`, `tapTile(tx,
ty)`, `tapButton('INTERACT' | 'slot 3' | text)`, `panel(name)`, `panelClosed()`, `idle()`, `frames(n)`,
  `event(name)`, `until(fn)`, `mutate(fn)`, `state()`, `shot(name)`, `strip(name, n, every)` (frame-exact strips),
  `load(name)`. `checker()` prints the PASS/FAIL lines every suite uses.
- **Production stays clean**: the dev tools are a lazy chunk imported only in dev builds or with `?debug`; the
  entry bundle holds only the dynamic import, the service worker never precaches the chunk, and `npm run build:store`
  (`.env.store`, `VITE_DEVTOOLS=0`) leaves it out entirely. `scripts/check-bundle.mjs` (in both verifies) proves it.
- **No new fixed waits**: `tests/fixed-waits.test.ts` fails on a new `waitForTimeout`/`sleep` over 100 ms (or a
  computed one) in `scripts/` or `agents/`; the existing ones are allowed per file in
  `scripts/fixed-waits-baseline.json` and may only go down (`UPDATE_WAITS=1 npx vitest run tests/fixed-waits`
  after removing some).

How the full run is laid out (`scripts/verify.mjs`): phase 1 runs lint, types, unit tests and the build, then e2e,
mobile, scenarios and onboarding (all five of its runs at once: 157 s instead of 276 s) side by side; phase 2 runs
`e2e-controls` alone with four phones (110 s instead of 215 s); phase 3 runs perf's three throttle levels side by
side (83 s instead of 233 s). Getting there: with controls beside the other suites, its gesture-timing checks (the
500 ms swipe, the 300 ms hold-and-drag) failed in 3 of 4 runs and passed every time alone, so it got its own phase;
a suite marked `retryAlone` that still fails beside others reruns once alone and the summary says FLAKY.

Per step before (serial): lint 18 s, typecheck 8 s, unit 17 s, build 6 s, e2e 81 s, mobile 28 s, controls 220 s,
onboarding 281 s, perf 234 s. The two moved blocks did not flake in the three "before" runs here: they were slow,
not flaky, on this machine. The latency flakes the coordinator saw are in `e2e-controls.mjs`, which I did not touch.

## Migration plan for the remaining scripts (after the merge)

1. **`e2e.mjs`** (42 fixed waits left): one block at a time onto scenarios. Title/new game and persistence stay
   (they test the title itself) but wait on `sceneReady`; the sleep flow waits on `panelOpen('summary')`; town projects
   (6c) gets a `town-projects` scenario (money, fiber, at the board) and `panel('board')` / `panel('projects')`;
   offline keeps its service-worker waits but polls `navigator.serviceWorker.controller`.
2. **`e2e-mobile.mjs`** (3): `openScenario` per profile instead of New Game.
3. **`perf.mjs`** (game-feel agent's): each sample becomes a scenario (`late-game-farm` already is the full field;
   add `town-night`, `woods-summer-night`, `storm-field`) and `loop.step` replaces the 1.5 s settle; its draw counter
   can read `__farm.dev.frameStats()`.
4. **`e2e-controls.mjs` / `bench-thumb.mjs`** (controls): `openGame` becomes `openScenario`; the latency checks
   measure from touch events already, keep them, but drop the settle `sleep`s for `farm.idle()`.
5. **`e2e-onboarding.mjs`**: starts on `day1-fresh` (and a second run on `guided-day2` to test day 2 alone, which
   halves its time); the bot's pacing sleeps are deliberate (a human pace) and can stay, listed in the baseline.
6. **Probes** (`agents/probes/*`, 181 waits) and the critics' tools under `*-critique/tools/`: rewrite on
   `scenario-template.mjs` as they are next needed; delete the ones that only reproduce a closed finding.
7. Then lower `scripts/fixed-waits-baseline.json` with each step; when a file reaches 0 it stays at 0.
